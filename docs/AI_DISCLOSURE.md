# AI 生成说明

本项目（**lspy**）是 LocalSend 协议的独立命令行实现。从单文件骨架到协议实现、安全校验、测试与 CI 脚本，整个开发过程大量使用大型语言模型（LLM）辅助生成。

本说明严格遵循 [AI 开发规范](https://github.com/styisme/ai-development-guidelines)（仓库内副本：[AI-DEVELOPMENT-GUIDELINES.md](AI-DEVELOPMENT-GUIDELINES.md)），在此透明界定 AI 与人类在项目中的实际分工与责任边界。

**最后更新：2026-11-15（v1.19.2）**

相关文档导航：[README](../README.md) | [CHANGELOG](../CHANGELOG.md) | [贡献指南](../CONTRIBUTING.md) | [开发约束](DEVELOPMENT_CONSTRAINTS.md)。

## 📊 参与比例

**核心声明：约 90% 的代码由 AI 直接输出（按行统计，含改造前的原始版本）；人类负责需求定义、方向决策、审阅、实机验证与发布。**

这个比例偏高，原因是项目形态本身：单文件 Python CLI、零第三方依赖、协议可对照公开文档验证，属于"生成后能立刻用真实收发验证"的类型。我们宁可写清 90%，也不写"全部由 AI 完成"却拿不出验证过程。

## 🤖 AI 深度参与的部分

- **协议实现**：`LspyServer` 的 `/info`、`/register`、`prepare-upload`、`send-request`、`upload`、`send`、`cancel` 全路由；v2 与 v2.1 的共享协商逻辑；`401 + X-LocalSend-Pin` 的 PIN 语义。
- **发现与探测**：组播 `224.0.0.167` 加入与收发、全网段广播、HTTP 深度扫描（多网卡遍历、双端口并发探测）、`scan --json`。
- **文件落盘与安全**：`safe_filename`（非法字符、控制字符、超长名、保留名处理）、`unique_path`（同名同大小不再被"已接收"静默跳过）、`safe_unzip` 的 Zip Slip 拦截（绝对路径 / 盘符 / `..` / 符号链接）、逐文件扩展名过滤与指纹名单。
- **续传逻辑**：会话内按已落盘偏移续传，修正了旧版把注册偏移重复计入的问题。
- **跨网中继**：ntfy.sh 通道、2400 字节分块（规避单条消息上限）、3 次退避重试、`__SHA256__:<hash>:<len>` 尾包校验、按消息 id 去重。
- **发送端**：v2.1 优先 + 404/405 回退、`HTTPSConnection` 不校验证书、MIME 推断、`register` 预注册、真实绑定端口回填。
- **Web 状态页**：纯内联 HTML（设备信息 + 最近接收记录），`--web` 自动打开。
- **i18n**：10 种界面语言的字典、菜单标题、发送向导、绑定端口等文案。
- **工程化**：`tests/test_lspy.py`（25 个用例，含 512KB 端到端收发与同名冲突）、`pyproject.toml`、`scripts/sync_version.py`、`.github/workflows/*`、本套 10 语言文档的初稿。
- **排雷脚本**：因源文件含尾随空格导致精确替换失败时，改用"切片拼接"脚本重写 `interactive_menu` / `main` 段。

## 🧑‍💻 人类参与的部分

- **需求定义**：项目要解决什么问题、保留单文件形态、必须与手机端 LocalSend 互通、必须能跨网。
- **方向决策**：明确"全面完善"的三条线（修缺陷、补功能、工程化），以及本轮要求"按 watchsend 结构重组文档、符合 AI 开发规范"。
- **事实性审阅**：核对文档中的命令、配置键、端点与默认值是否与代码一致；指出描述与实现不符之处。
- **实机验收**：在本机 Windows 上真实跑通 `serve` + `send` 双进程落盘、局域网 `scan` 发现真实设备、`pip install .` 后 `lspy --version` 正常。
- **发布决策**：合并、打 Tag、发 Release、对外公布文档，均由人类执行，AI 不自动发布。

## ⚠️ 已知局限与风险

1. **AI 无法真机运行**：协议互通只在"本机双进程 + 局域网发现到一台真实设备"范围内验证过，未经多机型、多版本 LocalSend 客户端交叉测试，互通性存在未知边界。
2. **单文件架构的代价**：约 1500 行的 `lspy.py` 缺少类型标注与静态检查，重构时天然依赖测试兜底；AI 大段改写曾出现尾部空格、编码、行尾差异导致的替换失败，需人工介入。
3. **安全声明不构成安全审计**：PIN、指纹名单、扩展名黑名单、自签证书都只是"降低风险"，属于字符串与路径层面的校验，**不得**被理解为已完成安全审计；HTTPS 不校验证书链，无法抵御中间人。
4. **跨网通道是公网明文**：ntfy.sh 话题即 PIN，PIN 泄露等于文件泄露，不适合传输敏感数据。
5. **AI 文档的时效性**：文档由 AI 起草，可能落后于代码；发现不一致时以代码与 `CHANGELOG.md` 为准并提 PR 修正（规范 7.1）。
