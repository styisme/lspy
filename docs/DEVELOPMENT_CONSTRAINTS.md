# 开发环境约束说明

本文件说明 **lspy** 在开发与验证阶段无法覆盖的环境、设备与测试条件，用于解释"哪些地方没有被完整验证过"，避免把未验证的能力当作已支持。

相关文档：[README](../README.md) | [AI 生成声明](AI_DISCLOSURE.md) | [贡献指南](../CONTRIBUTING.md) | [AI 开发规范](AI-DEVELOPMENT-GUIDELINES.md)。

**最后更新：2026-11-15（v1.19.0）**

---

## 1. 平台覆盖

| 项 | 状态 |
|---|---|
| Windows 10/11 | ✅ 开发与验证平台（PowerShell，Python 3.13） |
| macOS | ⚠️ 代码按跨平台写法实现，**未在真机运行** |
| Linux | ⚠️ 同上，仅依赖标准库，但**未在真机运行** |
| Python 3.8 | ⚠️ 按语法约束编写，**未在 3.8 解释器上实跑** |
| 无图形环境（headless） | ⚠️ 已做无 `tkinter` 的降级分支，但未在纯 headless 容器中验证 |

结论：Windows 是唯一被真实运行过的平台。CI 虽声明覆盖 Windows / Linux 与多个 Python 版本，但流水线尚未在 GitHub 上真实跑过（见第 4 节）。

## 2. 对端设备与协议互通

| 项 | 状态 |
|---|---|
| 本机双进程回环收发 | ✅ 多轮真实落盘（含 512KB 文件、同名冲突） |
| 真实局域网发现 | ✅ 曾用 `scan` 发现一台真实设备（ThinkpadL490 @ `192.168.3.35:53317`，v2.1 / http） |
| 与 Android LocalSend 实际互传 | ❌ **未完成**：开发环境没有可支配的手机 |
| 与 iOS / 桌面版 LocalSend 互传 | ❌ 未完成 |
| v2.1 `send-request` / `send` 与真实客户端联调 | ⚠️ 仅用自建测试服务端验证，未与第三方实现互通 |
| 大文件（>1GB）、海量小文件 | ❌ 未压测 |
| HTTPS 双向互传 | ⚠️ 仅自签证书对自建服务端验证，未与真实客户端联调 |

因此：**"能与 LocalSend 互通"是按协议文档实现的推断结论，不是全机型验证过的结论。** 若你要依赖互通性，请先在自己的设备上做一次真实收发。

## 3. 网络环境

- 开发网络为普通家用局域网（无 AP 隔离、无企业代理）。
- **组播可用性**未在"封组播"的企业网络中实测；HTTP 深扫正是为此设计，但仅在少数网段上跑过。
- **跨网（ntfy.sh）**联调依赖公网访问；仅在自建收发两端之间验证过分块、重试与校验，未跨真实运营商网络做长时间传输。
- **STUN** 探测仅在当前网络出口验证过一次，无多 NAT 类型覆盖。
- Windows 防火墙放通、端口占用、端口随机分配（`port=0`）等场景已手工验证。

## 4. CI / 发布

- `.github/workflows/ci.yml`、`.github/workflows/release.yml` 与 `scripts/sync_version.py` 均为本轮新增，**尚未在 GitHub Actions 上真实执行过**。
- 未配置任何发布密钥：不向 PyPI 发布，Release 仅附带构建出的 sdist/wheel。
- 未验证 Windows 与 Linux 的 runner 差异（编码、换行、路径）。

## 5. 测试深度

- `tests/test_lspy.py` 共 25 个用例，覆盖：文件名净化、解压穿越、配置指纹、i18n、`info` 端口、Web 页、v2.1 全流程、PIN、黑名单、扩展名过滤、错误 token、cancel、端到端收发。
- **未覆盖**：真实第三方客户端、超长会话、磁盘写满、权限不足目录、并发多发送端、跨平台路径语义差异。
- 核心校验函数有可重复测试（符合规范 4.3），但"AI 说没问题"不作为验证结论（规范 4.4）。

## 6. 已知的环境耦合

- Windows 下非 TTY 输出需切 UTF-8，否则代码页会把图标与非 ASCII 字符编坏（已用 `_configure_stdio()` 处理，仅在 Windows 重定向场景验证）。
- 配置目录固定在 `~/.lspy/`，Windows 解析为 `%USERPROFILE%\.lspy\`；无便携模式开关。
- 文件选择依赖 `tkinter`，缺失时降级为手输路径。
