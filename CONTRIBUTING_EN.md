# Contributing Guidelines

[简体中文](CONTRIBUTING.md) | **English**

Thanks for contributing to **lspy**! This project follows a lightweight but strict management convention: **Conventional Commits + SemVer 2.0.0 + CHANGELOG**.

> **About the origin**: lspy is an independent command-line implementation of the LocalSend protocol (Python, single file, standard library only), written from scratch — no official app sources are copied. Sibling GUI implementations are [OldSend](https://github.com/styisme/oldsend) and [WatchSend](https://github.com/styisme/watchsend); they share protocol ideas but no code. Related docs: [README](README_EN.md) | [CHANGELOG](CHANGELOG.md) | [AI Disclosure](docs/AI_DISCLOSURE.md) | [Dev Constraints](docs/DEVELOPMENT_CONSTRAINTS.md) | [AI Development Guidelines](docs/AI-DEVELOPMENT-GUIDELINES.md).

---

## ⚠️ About AI-Generated Code

Following the [AI Development Guidelines](https://github.com/styisme/ai-development-guidelines) (in-repo copy: [docs/AI-DEVELOPMENT-GUIDELINES.md](docs/AI-DEVELOPMENT-GUIDELINES.md)), the vast majority of code here is **AI-assisted** — especially protocol parsing, on-disk naming and resume, discovery probing, cross-network chunking, i18n and CI scripts.

When submitting a PR you must:

- State whether the change was generated by AI.
- **Manually verify the feature** (you must actually transfer a file, not only "it compiles").
- If you used AI too, mention the model and prompt direction in the PR description.
- For changes touching **auth and PIN, certificates and TLS, path and sandbox validation, protocol parsing, command execution, CI secrets and release scripts**, declare "reviewed line by line by a human".

## Local Development

### Requirements

| Component | Version |
|---|---|
| Python | 3.8+ (CI covers 3.9 / 3.11 / 3.13) |
| Third-party deps | none (standard library only; `tkinter` optional for the file picker) |
| Git | 2.x |
| OS | Windows / macOS / Linux |

### Commands

```bash
git clone https://github.com/styisme/lspy.git
cd lspy

python lspy.py --help                     # run without installing
pip install .                             # install the `lspy` command
python -m unittest discover -s tests -v   # full suite (87 tests)
python scripts/sync_version.py --check    # version consistency with CHANGELOG
pip install pyinstaller && python scripts/build_binary.py --clean   # standalone executable
```

The fastest local smoke test is two processes:

```bash
# terminal A
python lspy.py serve -p 53501 --no-multicast -d ./tmp_recv
# terminal B
python lspy.py send ./some.bin --ip 127.0.0.1:53501
```

### Cloud Build & Auto Release

- **CI** (`.github/workflows/ci.yml`): on push/PR, runs the full suite on Windows and Linux plus `sync_version.py --check` and a compile check.
- **Release** (`.github/workflows/release.yml`): a `CHANGELOG.md` change pushed to `main` first builds a standalone executable on `windows-latest` and on `ubuntu-latest` (`lspy-<version>-windows-x64.exe` / `lspy-<version>-linux-x86_64`), then builds the wheel and sdist, and finally publishes a GitHub Release carrying all four artifacts.
- **Naming**: `scripts/build_binary.py` owns the artifact names and takes the version from `CHANGELOG.md` — nothing is renamed by hand.

Version injection is local-friendly too:

```bash
python scripts/sync_version.py            # writes the top CHANGELOG version into lspy.py and pyproject.toml
python -m build                           # needs the build package; CI does this
python scripts/build_binary.py --clean    # needs pyinstaller; artifacts land in dist/
```

> On Linux, `sudo apt-get install -y python3-tk` keeps the tkinter file picker in the binary. Without it the script skips `--hidden-import tkinter` and the binary falls back to typed paths.

## Project Structure

```text
lspy/
├── lspy.py                     # single-file app (CLI + HTTP server + sender + cross-net + i18n)
├── cfdialog.py                 # bundled file-dialog library (upstream 0.3.0, verbatim, MIT)
├── lg/                         # cfdialog language packs (upstream 0.3.0, verbatim)
├── tests/
│   └── test_lspy.py            # unittest: units + end-to-end transfer
├── scripts/
│   ├── sync_version.py         # single-source version extraction & injection
│   ├── extract_release_notes.py # version + release notes for publishing
│   └── build_binary.py         # PyInstaller single-file executable (bundles cfdialog + lg)
├── docs/
│   ├── AI_DISCLOSURE.md
│   ├── DEVELOPMENT_CONSTRAINTS.md
│   └── AI-DEVELOPMENT-GUIDELINES.md
├── .github/
│   ├── workflows/ci.yml
│   ├── workflows/release.yml
│   └── PULL_REQUEST_TEMPLATE.md
├── README.md / README_EN.md / README_*.md   # 10 languages
├── CHANGELOG.md                # single source of version
├── CONTRIBUTING.md / CONTRIBUTING_EN.md
├── LICENSE / LICENSE-LocalSend / LICENSE-cfdialog
└── pyproject.toml
```

`cfdialog.py` and `lg/` are never edited locally: upgrade by replacing the files wholesale, and send behaviour changes upstream. lspy only calls it (`_cfdialog()` / `_dialog_pick_files()` / `_dialog_pick_folder()`) and disables its auto-elevation on load (`set_auto_elevate(False)`) — otherwise the first pick would try UAC/root and restart the process.

Inside `lspy.py` the sections run top-down: constants and config → logging and stdio → i18n → helpers (filename sanitising, unique paths, progress, HTTP opener) → discovery (multicast / broadcast / HTTP scan) → `LspyServer` → sender → cross-network → history and certificates → interactive menu → `main`.

## Commit Convention

Use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```
<type>(<scope>): <subject>
```

### Allowed Types

- `feat`: new feature
- `fix`: bug fix
- `docs`: documentation only
- `style`: formatting (no logic change)
- `refactor`: refactoring
- `perf`: performance
- `test`: tests
- `build`: build/packaging
- `ci`: CI configuration
- `chore`: chores (version bump, .gitignore)

### Common Scopes

- `core`: protocol core and negotiation
- `http`: HTTP server/client
- `discovery`: multicast, broadcast, deep scan
- `transfer`: sending, receiving, saving, resume
- `security`: PIN, lists, extension filter, path checks, TLS
- `cross`: ntfy.sh cross-network
- `web`: web status page
- `cli`: command line and interactive menu
- `i18n`: translations

### Examples

```
feat(transfer): resume interrupted uploads from on-disk offset
fix(security): refuse zip entries that escape the target directory
ci: verify CHANGELOG version consistency before packaging
docs: restructure README into the multi-language suite
```

AI-assisted commits should append `ai-assisted` to the commit body (guideline 3.5).

## Pull Request Process

1. Fork the repo (or work on a branch)
2. `git checkout -b feat/your-feature`
3. Change code, run the suite and perform one real transfer
4. Commit with Conventional Commits
5. Push and open a PR
6. Wait for green CI + human review

### PR Description Should Include

```markdown
## Changes
What was done, briefly

## Change Type
- [ ] feat / fix / refactor / docs / chore

## Related Issue
Closes #123

## Testing Method
- [ ] `python -m unittest discover -s tests -v` passes locally
- [ ] Real transfer verified (OS + peer LocalSend version)
- [ ] CI passed

## AI Generated?
- [ ] Yes (specify model and manual verification)
- [ ] No
```

> `.github/PULL_REQUEST_TEMPLATE.md` ships the three mandatory checks required by the guidelines: AI involvement disclosed, compiled/run on the target platform, security-sensitive code reviewed.

## Issue Submission

### Bug Report

Please provide:

- **OS and Python version**
- **Peer device model and LocalSend version**
- **Steps to reproduce**
- **Expected** vs **actual** behaviour
- Relevant excerpts of `~/.lspy/lspy.log`, plus `lspy --version` and `lspy info` output

- Describe the use case (e.g. "how do I discover devices on a multicast-blocked corporate network?")
- Reference implementations or protocol docs if you have them

## Versioning Rules (Strict Automation)

Follow [Semantic Versioning 2.0.0](https://semver.org/):

| Change | Version Bump |
|---|---|
| Incompatible changes (protocol behaviour, config keys, CLI args) | **MAJOR** |
| Backwards-compatible features | **MINOR** |
| Bug fixes | **PATCH** |

⚠️ **IMPORTANT**: `CHANGELOG.md` is the single source of the version. **Never edit `VERSION` in `lspy.py` or `version` in `pyproject.toml` by hand.** Add a CHANGELOG entry (e.g. `## [1.20.0] - 2026-12-01`) and let `scripts/sync_version.py` inject it; CI verifies consistency.

## Configuration Reference

File: `~/.lspy/config.json`, edited via `lspy config --set k=v`.

| Key | Default | Meaning |
|---|---|---|
| `alias` | hostname | Device name shown to peers |
| `port` | `53317` | Service port; `0` picks a free port |
| `save_dir` | `./downloads` | Receive directory |
| `pin` | none | Fixed PIN; when set the receiver requires it |
| `auto_accept` | `true` | Accept without confirmation |
| `filter_ext` | `exe,bat,cmd,vbs,sh` | Rejected extensions (skipped per file) |
| `whitelist` / `blacklist` | empty | Fingerprint lists, prefix matching; blacklist wins |
| `auto_accept_whitelist` | `false` | Auto-accept whitelisted devices |
| `use_https` | `false` | Use HTTPS for send and receive |
| `web_enable` | `true` | Serve the web status page |
| `organize_by_type` | `true` | Group saved files by type |
| `history_enable` | `true` | Append to `history.jsonl` |
| `history_max` | `300` | Max history entries kept; oldest dropped beyond it, `0` disables trimming |
| `clipboard_text` | `true` | Copy received `.txt` up to 10 KB into the local clipboard |
| `auto_unzip` | `false` | Auto-extract after receive (Zip Slip checks still apply) |
| `open_after_receive` | `false` | Open received files with the OS handler |
| `lang` | `auto` | `auto` or `zh/zh_TW/en/ja/ko/de/fr/es/ru/pt` |
| `ntfy_topic` | `oldsend_cross_` | ntfy topic prefix for cross-network |
| `log_level` | `INFO` | `DEBUG/INFO/WARNING/ERROR` |
| `fingerprint` | generated | Device fingerprint, regenerated if removed |
| `debug_keys` | `false` | Debug keys mode: render raw i18n keys in the UI |
| `force_cfdialog` | `false` | Send file selection straight to cfdialog, skipping tkinter (still falls back to typed paths without the library) |

## Protocol Implementation

Server routes (prefix `/api/localsend/v2`, also mounted under `/v1`):

| Endpoint | Method | Purpose |
|---|---|---|
| `/info` | GET | Device info (reports the actually bound port) |
| `/register` | POST | v2.1 pre-registration |
| `/prepare-upload` | POST | v2 pre-upload negotiation |
| `/send-request` | POST | v2.1 send request |
| `/upload` / `/send` | POST | Chunk upload (`fileId`/`sessionId` + `token`) |
| `/cancel` | POST | Abort a session and clean partial files |

The sender prefers `send-request` → `send`, falling back to `prepare-upload` → `upload` on 404/405. The cross-network channel uses ntfy JSON messages, 2400-byte chunks, with a `__SHA256__:<hash>:<len>` trailer.

Web share page (the whole group 404s when `web_enable` is off; with a PIN set every call needs it as the `pin` query parameter or the `X-LocalSend-Pin` header):

| Endpoint | Method | Purpose |
|---|---|---|
| `/`, `/index.html` | GET | Single-page UI: upload / download / text tabs, device info, recent receipts |
| `/web/info` | GET | Alias, port, version, whether a PIN is required, received file count |
| `/web/files` | GET | Files in the receive folder (relative path, size, mtime, max 500) |
| `/web/download?name=` | GET | Stream one file; `name` is validated by `web_safe_path`, so `..` and absolute paths are rejected |
| `/web/upload?name=` | POST | Raw body written into the receive folder via `safe_filename` + `unique_path` + the extension policy, max 2 GiB |
| `/web/text` | POST | JSON `{text}`: write to the local clipboard, or to `web-text-<time>.txt` when no clipboard exists |
| `/web/clipboard` | GET | Plain text of the local clipboard |

## Troubleshooting

**Q: My phone cannot find the computer.**
A: In order: (1) allow TCP/UDP `53317` (Windows Firewall prompts on first run); (2) check router AP isolation; (3) try `lspy scan -t 5` — the HTTP deep scan often works where multicast is blocked; (4) on locked-down corporate networks, dial directly with `--ip`.

**Q: The peer keeps answering 401 / asking for a PIN.**
A: The receiver has `pin` set. Pass `--pin` when sending, or clear it on the receiver with `lspy config --set pin=""`. The `X-LocalSend-Pin` header means a PIN is required.

**Q: One file is rejected and the whole batch fails.**
A: Since v1.19.0 extension filtering and the blacklist are evaluated **per file**; only the offending entry is skipped. If the batch still fails, check the `403` reason in `lspy.log`.

**Q: Will same-name files be overwritten?**
A: No. Landing names go through `safe_filename` + `unique_path`; conflicts become `(1)`. Identical name and size is never treated as "already received".

**Q: Why does a retried transfer resume mid-file?**
A: That is intended in-session resume from the on-disk offset. A new session (fresh `prepare-upload`) starts from zero.

**Q: `lspy serve` reports the port is in use.**
A: Use `-p 0` (or `lspy config --set port=0`) and read the actual port from `lspy info`.

**Q: Redirecting output to a file garbles Chinese text or icons.**
A: On non-TTY streams the program switches stdout/stderr to UTF-8; if it still looks wrong, make sure the reader decodes UTF-8 (or `chcp 65001` first).

**Q: Sending to an HTTPS device fails.**
A: Add `--https` (or `lspy config --set use_https=true`). Like LocalSend, certificate chains are not validated, so self-signed certificates work.

**Q: `--web` shows nothing.**
A: Confirm the service is running with `web_enable=true` and open `http://<bound-ip>:<port>/`.

**Q: No `tkinter`, the picker crashes.**
A: It degrades to typed paths automatically; install a Python build with Tk to get the dialog back.

**Q: CI complains about a version mismatch.**
A: `lspy.py` / `pyproject.toml` disagree with the top of `CHANGELOG.md`; run `python scripts/sync_version.py` and commit.
